3 · Inconsistencies found

The matrix lists them. In short:

  • Business logic differed in 12 places: checkout total, what happens after payment, how a subscription ends, what “paused” allows, readiness checks, status rules, filters, and the data collected for obligations, assets, documents, messages and people.
  • Six things existed on one platform only: the closed state, payment failed, the yearly review, item views, Save and exit in guided setup, and most prototype states. All six were missing on mobile.
  • The rest was wording: module names, button labels, empty states, figures, icons.
  • Inside mobile itself, the Vault used three names for sealed items and four for messages, and three different rules for “complete”.
  • Inside the web, the desktop and phone layouts disagreed on checkout, the step after payment, the next-step wording and several form labels.

4 · Changes applied

Mobile app

  • Five-step introduction replaces the single discovery screen.
  • Checkout button and exit wording; Profile “Cancel My Vault” now leads to Account and data.
  • New states: payment failed, yearly review due, paused (truly read-only), closed with Reopen.
  • Overview: same readiness checks, one next step, guidance labels, figures, row status.
  • Four sections rebuilt: descriptions, empty states, filters, item views, Remove wording.
  • Forms rebuilt on the web data model: obligation, asset, sealed document, message.
  • Trusted People: date of birth, invite status, Tell them now, Resend invite.
  • Four-step yearly review. Guided setup: Save and exit, corrected hints.
  • Home shows “N% ready” until the Vault is ready.
  • Every retired word removed.

Web · desktop and phone layout

  • Introduction: one page on desktop, five screens on a phone, same words.
  • One checkout and one confirmation for both layouts. Paying clears Paused and Closed.
  • Overview: one next step, same guidance labels, review-due rule, figures in CAD, same headings.
  • Section descriptions, empty states, form titles, hints and error messages now come from one place.
  • Messages: one “Add a message”; voice or video is chosen in the form.
  • Amount and value are optional; an empty one marks the item “Add details”.
  • People, release and account pages say the same thing in both layouts.
  • Paused also blocks adding people. Notices on pause, resume, close, reopen.
  • Home follows readiness in both layouts.
  • Short label “Documents”; sealed icon is a lock.

Files — web: desktop/vault.js, revamp/vault.js, revamp/vault.css, desktop/approved.css, revamp/config.js, revamp/will-lock.js, both index.html. Mobile: the “v44” layer in design/simulator-v41.html. The Will was not changed on either.

6 · Checks run

  • Same words, three surfaces. 23 screens and states were opened on the mobile app, the web on a phone and the desktop, and checked for the same required text and for retired words: 69 checks. 68 pass on the rendered text; in the last one the app keeps the asset categories inside a closed picker, so the list was confirmed in its source instead. Covered: the five introduction steps, checkout, the Overview in seven states, the four empty sections, two add forms, Trusted People, Release settings, Reminders, Account and data.
  • Web journey, both layouts: not subscribed → introduction → Start My Vault → pay → confirmation → Open My Vault → add asset → view → edit → back → add obligation → filter → pause → resume → close → reopen. Same steps and messages.
  • Web sweep: 9 states × 42 routes on both layouts. No script errors, no blank or “undefined” text, no sideways scroll at 390 and 1440 pixels.
  • Mobile: the session that built the mobile layer reports every Vault state rendering with no script errors. The full add → view → edit journey on mobile was not re-run independently here.
  • Not checked: a screen reader, widths between 390 and 1440, real recording or upload (the prototypes store names only), and the mobile forms field by field against the web by a person.

7 · Still open

Small differences left

  • A. In guided setup, the message step offers four delivery options on the web; the full form and the mobile app offer five (“On a life event”).
  • B. Mobile checkout uses its three-step header instead of the title “Start My Vault”, and asks for a Terms tick.
  • C. “Go to the next item” opens the section on mobile; on the web it opens the exact item when one needs fixing.
  • D. In the yearly review, “Change” opens the item view on mobile and the form on the web.
  • E. Mobile list rows tag obligations with the short kind (“Bank debt”); the web groups them under headings.
  • F. The final fallback can still be signed while the Vault is paused on the web.
  • G. “Plan and billing” is a desktop page; on a phone and in the app the plan sits in Account and data.

Business questions

  1. Tax and referral code. The app charges $9.03 (GST 13%) and accepts a referral code. The web charges $7.99 with neither. Which is right? Is 13% GST or Ontario HST?
  2. Paused price. Both say “at a lower price”. What is it?
  3. Release conditions. The introduction now states that nothing is released until a death certificate or a hospital letter is verified. Is that confirmed by operations and legal?
  4. Amount optional. An obligation or asset can now be saved without a value and is marked “Add details”. Acceptable?
  5. Second executor. The Vault shows an executor order, but the Will collects one executor. The Will is frozen.
  6. Home when paused or payment failed. Should Home still say “Up to date”?
  7. Vault before the Will is complete. The web shows “Preview · activates after attestation”. The app does not. Is the Vault usable before the Will is signed?
  8. Telling recipients. Recipients are contacted only when the owner chooses “Tell them now”. Confirm.
